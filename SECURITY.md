# Security Policy

## Supported Versions

D3X8 is under active development. Security fixes are generally applied to the latest code on the `main` branch. Older commits and experimental builds may not receive fixes.

| Version | Supported |
| --- | --- |
| Latest `main` | Yes |
| Older commits and releases | No guarantee |

## Reporting a Vulnerability

Please do not disclose suspected security vulnerabilities in a public GitHub issue, discussion, or pull request.

Use GitHub's **Report a vulnerability** option in the repository's **Security** tab to submit a private report, if private vulnerability reporting is enabled.

If that option is unavailable, contact the repository maintainer privately through their GitHub profile: <https://github.com/jadeking5128-beep>. Do not post exploit details publicly while waiting for a response.

When reporting, include as much of the following as possible:

- A clear description of the vulnerability and its potential impact.
- The affected commit, version, subsystem, or file paths.
- Steps to reproduce the issue, including relevant configuration and hardware or emulator details.
- A proof of concept or logs, if safe to share.
- Any suggested mitigation or fix.

Please avoid accessing, modifying, or deleting data that is not yours, disrupting services, or testing against systems without permission. Stop testing once you have enough evidence to demonstrate the issue.

## Response and Disclosure

The maintainer will review reports as time and project activity allow. Please allow reasonable time for investigation and remediation before making a public disclosure. No fixed response or remediation time is guaranteed.

Once a fix is available, the project may publish an advisory describing the impact, affected versions, and mitigation.
